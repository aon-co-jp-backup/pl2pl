# pl2pl — заметки для разработки
- **Назначение**: конвертер между языками, фреймворками и операционными системами (CLI на Rust, `src/`). Исходные языки перечислены в `docs/LANGUAGES.md`, сочетания — в `docs/COMBINATIONS.md`. Проект владелец понемногу пишет в `docs/DESIGN.md`. **Не придумывайте спецификацию за него.**
- **Направление**: преобразование «многие во многие» между известными языками и фреймворками. Не всё сразу — сначала выбранное. На сайте только инструкции и загрузка; преобразование выполняется в приложении для ПК.
- **Правила**: то, что нельзя преобразовать, остаётся как `TODO` и попадает в отчёт (никогда не удалять молча). Судить осторожно (если возможны зависимости или побочные эффекты — не преобразовывать). Прежде чем сказать «готово», запустить по-настоящему. Новых REST не делать. Отвечать только по-японски.
- **PHP**: `src/php.rs`, `src/blade.rs`, `src/middleware.rs`. Сквозной тест: `tests/run-php.sh` (настоящие FastAPI, SQLite, Jinja2); модульные тесты: `cargo test --release`. В WSL: `wsl -d Ubuntu -- bash <файл>`.
- **Автоматическое слежение**: `pl2pl watch` (`src/watch.rs`, `registry/ecosystem.toml`). Записи без команды проверки лишь показываются как «не проверено» и сами никогда не обновляются. Уведомления идут через `--notify-file` в version-control.
- **Подводные камни**: файлы с японским текстом писать через Python `-X utf8`; shell-скрипты хранить с LF; Git Bash переписывает пути `/mnt/...`; для строк с множеством кавычек использовать инструмент Write, а не heredoc.
- **COBOL_to / Java_to**: уже включены в `converters/`. Удаление исходных репозиториев необратимо — сначала получить окончательное подтверждение.
- **Система перевода** (естественный язык) отделена от конвертеров. Конвертеры не зависят от LLM.
- **Языки документации**: оригиналы на японском и ещё девять языков в `docs/i18n/` (переводы ИИ, носителями языка не проверены). Меняется оригинал — обновляйте переводы. Прежняя история: `docs/HISTORY-ja.md`.
