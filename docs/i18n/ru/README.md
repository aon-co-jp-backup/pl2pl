# pl2pl
pl2pl преобразует код между языками программирования, фреймворками и операционными системами. Сейчас это версия 0.1.0, проект активно развивается. Есть установщики для Windows (x64/ARM64), Linux (amd64/arm64) и macOS (arm64/x64). Преобразование выполняется в установленном настольном приложении (в командной строке); на сайте размещены только руководства и ссылки для скачивания.
Конвертер намеренно осторожен. **Всё, что не удалось преобразовать, никогда не пропадает молча: оно остаётся в результате как `TODO` и попадает в отчёт вместе с причиной.**

## Что работает сейчас
| Команда | Что делает |
|---|---|
| `pl2pl cobol` | Преобразует IBM COBOL вместе с JCL в GnuCOBOL под Linux и скрипт bash. Проверено: результат собран и запущен в GnuCOBOL. |
| `pl2pl omp` | Добавляет `#pragma omp parallel for` к независимым циклам C/C++, в том числе с редукцией суммы. Результат совпадает с исходным. |
| `pl2pl php` | Преобразует Laravel / Symfony в FastAPI (подробности ниже). Сквозное тестирование проведено на настоящих FastAPI, SQLite и Jinja2. |
| `pl2pl web` | Определяет Java, COBOL и Flask/Django и передаёт работу java_to, cobol_to, 2fastapi или 2poem. Проверено на реальных файлах. |
| `pl2pl cport` | Превращает код на C для UNIX в заголовок совместимости с механическими заменами и заметками по переносу. Проверено с gcc. |
| `pl2pl pyhpc` | Добавляет Numba `@njit` к числовым функциям на Python; с `--mpi` ещё создаёт заготовку на mpi4py. Под Numba результат тот же. |
| `pl2pl kokkos` | Переписывает независимые циклы на Kokkos (`parallel_for` / `parallel_reduce`). Собрано и запущено с Kokkos 4.5.01 (Serial). |
| `pl2pl gpu` | Прототип: превращает циклы в `.cu` в стиле CUDA или в HLSL. Проверен только сгенерированный вывод; запуск на open-cuda / open-directx пока не проверялся. |
| `pl2pl llm setup` / `llm start` | Запускает встроенный aruaru-llm и ставит модель Qwen2.5, подходящую по объёму свободной памяти. Проверены только выбор модели и `--dry-run`, реальная установка — нет. |
| `pl2pl doctor` | Показывает сведения о процессоре через встроенный open-cpu. |

## Преобразование PHP (`pl2pl php`)
- **Маршруты**: Laravel `Route::get/post/put/patch/delete/any/resource/apiResource/view`, группы `prefix` и Symfony `#[Route]`.
- **Тела функций**: простой `return`, тела из нескольких операторов, `response()->json($x, 201)` и `noContent()`.
- **Eloquent → SQLAlchemy** (`db.py`, `models.py`): столбцы берутся из миграций или `$fillable`, всё остальное попадает в JSON-столбец `extra`. База данных задаётся через `DATABASE_URL` (по умолчанию SQLite).
- **Конструктор запросов**: `where / orWhere / whereIn / orderBy / latest / oldest / limit / take / offset / skip`, `paginate / simplePaginate` (читает `?page=N`, возвращает JSON в формате Laravel, в Blade работает `links()`), `get / first / firstOrFail / count / exists / delete` и `$request->query('k', значение по умолчанию)`.
- **Связи**: `hasMany / hasOne / belongsTo / belongsToMany` (промежуточная таблица создаётся автоматически), `with`, в том числе вложенный `with('posts.comments')`, `whereHas / has / whereDoesntHave / doesntHave`, а также `attach / detach / sync`.
- **Blade → Jinja2**: вывод значений, `@if`, `@foreach`, `@forelse`, `@for`, `@extends/@section/@yield/@include` и другое.
- **Middleware → `Depends`**: `auth` (лишь простая проверка Bearer — **её нужно заменить настоящей аутентификацией**), `guest`, `throttle:N,M` и собственные middleware вида «отклонить при условии, иначе `return $next($request)`».

## В планах (пока не сделано)
- PHP: связи `morph`, `cursorPaginate`, компоненты, стеки и директивы авторизации Blade, а также middleware, который обрабатывает ответ после `$next`.
- Когда COBOL_to и Java_to созреют, влить их в pl2pl и удалить исходные репозитории. Это указание владельца; поскольку удаление нельзя отменить, после слияния его подтвердят ещё раз.
- Общее промежуточное представление (серверная часть, база данных/SQL, интерфейс), чтобы для N источников и M целей нужно было N+M компонентов, а не N×M.
- Интеграция с aruaru-llm. Пояснения и перевод естественного языка остаются отдельно от конвертеров, а сами конвертеры никогда не зависят от LLM.
- Kokkos на GPU и `Kokkos::View`, а также запуск ядер на open-cuda / open-directx.
- Запуск новых примеров PHP в CI на Linux arm64 и macOS и добавление новых пар языков из `docs/LANGUAGES.md` (все комбинации делать не будем).

## Что стоит знать
В сомнительных случаях pl2pl выбирает осторожность. Если у конструкции могут быть зависимости или побочные эффекты, она **остаётся непреобразованной, а причина указывается в отчёте**; производительность не обещается. Пока проверялись лишь небольшие примеры, написанные вручную, но не крупные реальные программы.
